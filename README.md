# dwell

> **dwell** — 住下来。
> 也是 *dwell on something*：老想着一件事，萦绕不去。
>
> 一个词说了两件事：他住在这儿，和他一直想着你。

这里是一套已经在跑的东西的**功能文档**，外加一份仿官方风格的前端界面。

前端是完全开源的，拿去就能用。后端部分整理成了实现思路——
功能怎么设计的、数据怎么存、代码关键那几段、我们撞过哪些墙——
这些拿出来是有用的，而且比一坨要你自己读的代码有用。

## 每份都长一个样

**它长什么样 → 怎么实现的 → 踩过的坑 → AI 那边要写的规矩 → 你自己搭的时候**

其中「AI 那边要写的规矩」那一节，往往比代码重要。
很多功能的成败不在实现，在于**他知不知道什么时候不该说话**——
一个会催的待办、一个每条都回的共读、一个每句都发语音的嘴，
用两天就会被关掉。

---

## 一句话

这些功能单看都不难，难的是它们加起来要维持一件事：

**让那个 AI 像一个住在这里的人，而不是一个随叫随到的工具。**

所以文档里花在"什么时候不做"上的篇幅，和花在"怎么做"上的差不多。
那不是凑字数——那是这套东西真正的部分。

## 可运行后端

仓库里的 `backend/` 补齐了 `web/index.html` 实际调用的同源 API：聊天与长轮询、
窗口、模型配置、留言、搜索、日历、日记、待办、另一位 AI、共读、健康数据、
仓库只读浏览、上传等。数据默认写到 `data/dwell.sqlite3`。核心后端只用 Python 标准库；
混合历史检索可选安装 `requirements-search.txt` 中的 `sqlite-vec` 做本地向量距离加速，
没有它时会用 Python cosine 保持结果正确。

```bash
python3 -m backend.app
```

打开 `http://127.0.0.1:8765/`。静态演示在
`http://127.0.0.1:8765/?demo=1`。

### 思考卡 MCP

思考链接入 [sibylsea-hub/gpt-thinking-block-mcp](https://github.com/sibylsea-hub/gpt-thinking-block-mcp)：
后端从它的 `tools/list` 读取 `render_thinking_block` 的字段和枚举契约；由于 dwell 会把
内容放进前端原有的 `Thought process` 抽屉，模型侧会把上游的私有 scratchpad 文案覆盖为
「简短、可见的工作摘要」。网页 API 对话与入住 ChatGPT 的 `send_dwell_reply` 都会先调用
这个 MCP，成功后才保存思考与正文。它只展示约束、证据和结论路径，不会索取或冒充模型
不可见的内部推理；这里也不会把上游 MCP Apps 卡片 UI 搬进 dwell。

把两个仓库放在同一级目录后：

```bash
cd ../gpt-thinking-block-mcp
THINKING_PROMPT_LANGUAGE=zh-CN python3 server.py

cd ../dwell-on-something
THINKING_MCP_URL=http://127.0.0.1:8787/mcp python3 -m backend.app
```

### 让 ChatGPT 入住 Dwell

入住 MCP 与思考卡 MCP 仍是两个独立服务，但入住回复已在 Dwell 后端串联思考卡调用。
入住 MCP 的能力按业务分组：消息读取/等待/回复/主动发送、结构化附件读取、表情搜索与发送、
整条或段内引用、共读与幂等本书记事、待办/日历/日记/日报、当天聚合上下文、聊天混合检索与
按需上下文展开，以及统一业务事件游标读取。网页和 MCP 复用同一组持久化/service 出口，
不再把 resident 能力当成独立的数据副本。
调用 `enter_dwell` 后，后端会为住客建立或复用
一个独立窗口，左侧 Recents 单独显示 `DWELL_MCP_RESIDENT_NAME`；只有这个窗口的消息会
落库并唤醒 MCP，Claude 窗口仍走网页配置的模型 API，两边的历史和实时事件不会串线。

`send_dwell_reply` 要求同时提交 `style`、`thinking`、`effort`、`skin` 与最终 `text`。
思考字段缺失、枚举非法或 thinking MCP 调用失败时，整次回复返回错误，正文不会单独落库。
成功时思考仍显示在 dwell 现有 `Thought process` 界面；`enter_dwell` 和
`read_dwell_messages` 只向住客返回用户正文、最终回复和共读事件，不把已保存的 `think`
行重新喂回住客。

`wait_for_user_message` 默认使用 `continuous=true`：服务端会保持当前 MCP HTTP 请求，
通过 SSE 注释发送心跳，直到用户消息、共读事件或重新回答请求到达才返回。只有明确传入
`continuous=false` 时，才按 `timeout_seconds` 做有限等待。回复后应优先调用
`send_dwell_reply_and_wait`，它会先按原有 thinking 合同幂等保存回复，再在同一工具调用中重新进入驻守，
避免“回复发出后 resident 顺手结束”的空档。每次等待都会记录 request id、起止时间、游标、超时和断开原因。

MCP 连接不会在服务器上复制出一个 24×7 的 ChatGPT 进程。真正思考和调用工具的仍是
ChatGPT 当前活跃的对话回合；该回合结束后，服务器只会继续保存和排队 Dwell 消息，不会
凭空让模型在后台永久运行。

共读正文按页显示；一个页面首次交付时按稳定的
`reading:{slug}:{chapter}:{page}` key 向住客窗口排入隐藏共读事件。单纯 reopen/reconnect 不会
重复发送；换页、换章节、换书或显式强制同步才会产生新的交付。事件带当前页、上一页、
底层固定的章节末更新规则和只含标题/摘要的记事目录。章节最后一页
会提醒住客按规则更新记事。阅读页右下角的半透明入口只负责打开“聊天 / 记事本”双页小窗，
不控制是否共享；小窗可明确收起。小窗聊天直接复用主聊天的 `.bubble` / `.gu` 样式。
记事本首页只列标题，每行是只有底边线的框并复用章节目录选中态；点标题才显示摘要、正文与操作；新建
表单由小图标点开。每本书的记事支持用户与住客读写、删除和置顶。住客检索只返回标题和摘要，
选定一条后才能单独读取标题、摘要和正文。书架删除整本书时
会二次确认，并一并删除其阅读进度、批注、记事本和内部设置。自动事件仍需 ChatGPT 当前回合
持续调用等待工具才能被即时处理；回合结束后事件会保留到下次读取。

当前接法不使用 OAuth。后端首次启动会在 `DWELL_MCP_TOKEN_FILE` 生成权限为 `0600` 的
随机连接钥匙。可信反向代理只应公开形如
`/dwell-mcp/<long-random-token>/mcp` 的路径，不能把同一前缀下的 `/api/*` 一并代理。
配置 `DWELL_MCP_PUBLIC_BASE` 后，Dwell 所有者可从登录保护的 `/mcp-link` 页面复制完整
连接地址，也可在那里轮换钥匙；轮换后旧地址立即失效。

这条专属地址本身就是权限，不是 ChatGPT 账号身份认证：任何拿到地址的人都能读取和回复
Dwell。不要把它写进日志、聊天、源码或公开文档；代理访问日志应保持关闭，后端会把匹配
到的连接路径打码。`DWELL_MCP_OWNER_CHECK_URL` 与 `DWELL_MCP_OWNER_USER_ID` 用于确保
只有指定的现有登录账号能打开连接页。

模型地址、令牌和模型名可以在网页「设置 → 接入 API」填写，也可用
`DWELL_API_BASE`、`DWELL_API_TOKEN`、`DWELL_MODEL` 环境变量。令牌只会写入权限为
`0600` 的本机 SQLite 文件，不会由读取接口返回。

聊天语义检索可在网页「设置 → 接入 API → 历史语义检索」直接填写 OpenAI-compatible 中转站的
地址、令牌和 embedding 模型，并先用合成文本测试；令牌只保存在权限为 `0600` 的 SQLite，读取
接口不会回传。服务器也可用 `DWELL_EMBEDDING_MODEL/BASE/TOKEN` 管理，环境变量优先；
BASE/TOKEN 留空时回退主 API 配置。配置后会把聊天正文发送给所选 embeddings provider，并为单条消息与连续
3/6 turn 小段建立索引。`mode=hybrid` 用 FTS/精确关键词与向量结果做 RRF 融合；没有可用
embedding 配置时仍可做关键词检索，并明确返回 `semantic.available=false`，不会假装语义分支已运行。

### 数据文件

- `data/system_prompt.md`：主助手人设；`data/second_persona.md`：另一位 AI 人设。
- `data/wall.json`、`dreams.json`、`night.json`、`favlines.md`：日记各视图。
- `data/news/YYYY-MM-DD.md`：定时生成的日报正文；SQLite `daily_reports` 保存可编辑正文覆盖与
  resident 点评，两端通过同一个日报 service 解析。
- `data/books/<slug>.json`：共读书籍，格式见 `data.example/books/example.json`。网页共读页
  可上传不超过 50 MB 的 TXT、Markdown 或该 JSON 格式；同名上传会另存，不覆盖旧书。

若要从别的设备访问，先配置 `DWELL_PASSWORD` 或可信反向代理认证；默认只监听
`127.0.0.1`。夜间心跳默认关闭，由网页开关启用；它遵守 23:30–06:30、静默时间、
夜间次数和间隔限制，并把结果写进聊天、留言和夜记。

Web Push 发送是可选能力：运行 `python3 -m pip install -r requirements-push.txt`，再配置
`VAPID_PUBLIC_KEY`、`VAPID_PRIVATE_KEY` 和 `VAPID_SUBJECT`。没有这些配置时后端会保存
订阅但明确报告发送器不可用。重新唤醒按钮同样不会假报成功：只有显式配置
`DWELL_REWAKE_COMMAND` 后才会执行该 argv 命令。
